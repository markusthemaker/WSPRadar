1. Choose and Prepare the Analysis

Start with one station question. State what you changed or want to investigate, and which observation would help answer it.

1.1 Prepare your station and reports

  1. Create usable reports. For RX, configure a WSPR-capable receiver and decoder, such as WSJT-X, with the correct receiving callsign, locator, band, audio input and synchronized clock. Enable uploads: a local decode that was never uploaded is unavailable to WSPRadar. For TX, configure the callsign, locator, band, timing and truthful transmit-power report; remote receivers provide the spots. The WSJT-X reference covers basic setup.
  2. Verify the database identities. Check the exact RX reporting callsign or TX callsign, reported locator and UTC times in WSPRnet, then in the database WSPRadar will use. Use the callsign exactly as recorded, including any existing suffix. Choose a completed period and allow reports to arrive; no fixed delay guarantees completeness. See data troubleshooting.
  3. Keep the setup interpretable. Record the antenna, feedline, radio, decoder, gain or power settings, software, schedule and deliberate changes. Keep other variables stable and clocks synchronized. For Benchmark, prepare both setups using RX guidance or TX guidance before collecting the comparison.

1.2 Configure your analysis

Choose the analysis from Section 0.1. Guided leads you through the settings; Compact presents the same scientific choices in a shorter form.

Enter the exact Target callsign, Target QTH (Maidenhead locator), one band, and a completed UTC window. Target QTH accepts four or six locator characters: the first four select reports, while the full entered locator anchors the map, distances and directions. Longer windows add evidence but can mix operating and propagation conditions.

For Benchmark, enter one exact Reference callsign different from the Target callsign. Leave its optional QTH blank to discover the location from reports, or enter its independently known four-character locator. Choose explicitly if several locations are found. A location does not prove operation or physical co-location.

Confirm the operating conditions independently:

  • RX Benchmark: both receivers listened on the selected band with functioning uploads throughout the period. This does not require a decode in every cycle.
  • TX Benchmark: both transmitters sent in the same WSPR cycles, with aligned schedules and message patterns.

Keep supporting operating records. WSPRadar records your confirmation; it cannot verify continuous operation from successful reports. Historical replay, used by the maintained Milazzo example and saved replay configurations, describes historical reports without independently verified common operation. It requires acknowledgement of those limits, rather than a claim of controlled operation; see Section 10.3.

Leave Reference SNR correction at No correction unless you have an independently established offset valid for this setup. See calibration guidance.

For the first run, review the displayed filters and evidence requirements without lowering them merely to obtain more colored map areas. Maximum peer distance from Target (km) changes which remote stations enter the analysis, not just the map zoom; choose it to match your question. See scope and evidence controls. Check the final summary, then select Run RX Analysis or Run TX Analysis. Exact controls are in Chapter 10; unexpected gaps are addressed in Chapter 11.

1.3 Navigate the results

Use one path through the results, rather than trying to read every panel at once. Open How to read this beside a view whenever you need its legend, counting rules or interpretation.

1. Global View — where is the pattern? A map segment covers a range of directions and distances from the Target. Read its numerical scale and supporting counts. An uncolored area is not automatically zero reception; check whether evidence is absent or below the required minimum.

2. Segment Inspector — how broad and persistent is it? Choose the directions and distances to examine. This active scope controls the segment statistics and temporal figures. Compare station and observation counts, then check individual dates before calling a combined UTC-hour pattern recurring. In Benchmark Statistics, compare the spot-pair and station-median ΔSNR distributions: frequently observed stations contribute more to the first.

3. Station Insights → Selected Station Evidence — which stations explain it? Select a typical station, an unusual one, or a station contributing many reports. Performance follows the Inspector scope. In Benchmark, the station list is global by default; Filter by selected segment and distance optionally narrows the list, while selected-station evidence keeps the full run. In Benchmark, enable Include one-sided evidence to inspect identities without spot pairs and one-sided Drill-Down observations.

4. Drill-Down — what happened in individual cycles? Check exact identities, UTC times, SNR and outcomes. A focused time window helps inspect a particular interval. These are processed observations after matching and filtering, not an untouched database download.
